# 38. 세션 GS — Hand Tracking

- 담당자: **GS Hand Tracking**
- 브랜치: `feature/game-sensor-tuning`
- 담당: 빠르게 흔드는 손 인식 개선 (G3 사람 검증 중 사용자 보고)
- 수정 가능: `Tools/HandSensor/**`, 이 문서
- 선행 조건: G3 `main` 병합. 조사 중 사용자가 손을 흔들어야 하고 웹캠을 점유함

## 1. 문제

사용자 보고: "유저가 손을 빠르게 흔들었을 때 센서가 그 손을 제대로 인식을 못한다."

실드는 빠른 흔들기(`motion >= 0.8`)로 발동하므로, 이 문제는 게임 조작에 직접 영향을 줄 수 있다. 단, G3 사람 검증은 이 상태로 통과했다. **원인은 측정되지 않았다.**

## 2. 조사 순서

**원인을 측정한 뒤 고친다.** 추측으로 임계값부터 바꾸지 않는다.

1. 기준선 기록: `--preview` 상태로 약 20초씩, 손을 천천히 흔들 때와 빠르게 흔들 때의 `fps`, `hands`, `held`, `inferMs`
2. 조명 비교: 현재 조명과 밝은 조명에서 1을 반복. 카메라 fps 변화 기록
3. 측정 결과에 따라 시험

| 가설 | 근거 | 시험 |
|---|---|---|
| 모션 블러로 손을 놓침 | 어두우면 카메라가 약 15 fps, 노출이 길어짐 | 밝은 조명, 수동 노출 |
| 카메라 설정 미적용 | `open_camera`가 해상도만 설정, `cameraFps` 미사용. 이전에 MJPG/30fps 요청이 무시된 기록 있음 | FOURCC, fps, 노출 요청 후 실제 적용 값 확인 |
| 인식 신뢰도가 높음 | 현재 0.5 | 낮춘 값에서 놓침과 오검출 비교 |
| 놓친 동안 강도 감소 | 0.3초 hold 동안 위치 고정, `v` 감소 | hold 시간과 감소 곡선 비교 |

여러 조건을 한 번에 바꾸지 않는다. 시험마다 조건 하나만 바꾸고 수치를 기록한다.

## 3. 제약

- UDP 패킷 형식과 포트 변경 금지. Unity 코드 변경 금지
- 카메라 설정 추가가 필요하면 `config.json`의 기존 필드만 사용. 새 필드가 필요하면 기획 세션에 요청
- 오검출(손이 없는데 인식)이 늘어나는 변경은 수치와 함께 보고
- 하드웨어 한계로 판단되면 코드를 억지로 바꾸지 말고 "조명 조건"과 측정값을 결론으로 보고. 이것도 정상적인 결과임

## 작업 로그

### 2026-11-06 측정과 결론

조건: Logi C270, 640×480, 손+Pose+미리보기 포함 파이프라인. 조명: 방의 밝은 등을 켠 상태 (사용자 확인, 조도 미측정, 측정 중 조명 변경 여부는 미확인). 조명 밝기를 바꿔 비교하지는 않음. 놓침 = 손 0개 프레임 비율. 속도 단위 = 화면 폭/초.

**결론: 주원인은 모션 블러. 노출을 줄이면 해결된다.** 놓침 정도는 손 속도에 크게 좌우되어 같은 자동 노출에서도 0.4~36.1%로 달라진다. 추가로 다시 잡은 손을 새 손으로 처리하는 `hand_tracker.py` 결함을 찾아 고쳤다.

한 손 빠른 흔들기 (실측):

| 측정 | 노출 | fps | 밝기 | 속도 중앙값 | 놓침 | 최대 끊김 | `v>=0.8` (변경 전 → 후) |
|---|---|---|---|---|---|---|---|
| base2 | 자동 | 24.1 | 145 | 1.85 | 36.1% | 0.21초 | 42.1% → 79.3% |
| repA | 자동 | 24.1 | 143 | 1.59 | 13.9% | 0.16초 | 51.7% → 54.1% |
| repB | 자동 | 24.1 | 144 | 1.15 | 0.4% | 0.05초 | 64.9% → 64.9% |
| exp6 | -6 | 29.8 | 97 | 1.67 | 1.7% | 0.03초 | 83.9% → 84.1% |
| exp7 | -7 | 29.7 | 71 | 1.83 | 0.0% | 0 | 92.9% → 92.9% |
| rep7 | -7 | 29.7 | 54 | 1.33 | 0.0% | 0 | 91.8% → 91.8% |

`v>=0.8`은 `hand_tracker.py` 매칭 변경 전후를 같은 측정값으로 재계산한 값이다. 노출 줄인 조건은 fps도 함께 올라 두 조건이 분리되지 않는다 (C270에서 fps만 따로 바꿀 수 없음).

원인 판단 근거:
- 느린 흔들기(속도 0.69, 자동 노출)는 놓침 0%
- 속도가 거의 같은 base2(1.85, 36.1%)와 exp7(1.83, 0.0%)의 차이는 노출 조건뿐
- 프레임마다 손을 새로 찾는 IMAGE 모드 재생: 느릴 때 1.0%, 빠를 때 71.8%
- 움직임 영역 선명도(Laplacian): 놓친 프레임 139, 잡은 프레임 177 (base2)
- 한계: 측정 순서를 섞지 않았고 사용자가 뒤로 갈수록 느려졌다 (자동 노출 3회의 속도 차). 조건별 1~2회다

시험하고 적용하지 않은 것 (base2 빠른 흔들기 재생, 기준 놓침 34.2%):

| 변경 | 놓침 | 판단 |
|---|---|---|
| 신뢰도 3종 0.1 | 18.5% | 미적용 |
| presence만 0.1 | 17.4% | 미적용. 손 1개를 2개로 잡는 프레임 13개, BODY 구간 오검출 (`v>=0.8` 0.8%, 현재 값은 0%) |
| detection만 0.1 | 33.2% | 효과 거의 없음 |
| tracking만 0.1 | 34.2% | 효과 없음 |
| IMAGE 모드 | 71.8% | 악화 |
| hold 0.5초 | 34.2% | 놓침 무관. `v>=0.8` 54.8% |
| grace 0.5초 | 34.2% | 유령 점 52.3%로 악화 |

카메라 설정 적용 확인: MJPG 요청 무시(YUY2 유지), 30 fps 요청 무시(24.1 fps), 수동 노출 적용. 밝기 -5: 126, -6: 86, -7: 53, -8: 29 (카메라 단독 측정).

적용한 변경:
1. `--exposure N|auto` (`hand_sensor.py`, 기본값은 카메라 설정 유지라 동작 변화 없음)
2. 매칭 거리에 `4.0 × 놓친 시간` 추가 (`hand_tracker.py`). 끊긴 뒤 새 손으로 처리된 횟수 base2 52 → 3, 유령 점(손 1개인데 2개 송신) 25.9% → 1.7%. 2/4/6 비교에서 4와 6이 같았다. 느린 흔들기, BODY 구간은 전후 동일

기타 측정:
- 오검출(현재 신뢰도): EMPTY 3회 0프레임 후 재검출 없음, BODY 30초 전 프레임 송신 없음
- 정지한 손(안정화 2초 이후): `v>=0.8` 0프레임. 최대 v 자동 0.12, -7 0.04
- 몸 인식률(빠른 흔들기 재생): 자동 98.8~100%, -6 97.8%, -7 97.5~98.3%
- 양손 빠른 흔들기, 두 손 모두 잡은 프레임: 자동 72%, -7 79%. 손 1개 기준 놓침 약 17% / 12% (추정). 노출로 다 해결되지 않으며 원인 미확인

측정 못 한 것과 남은 문제:
- 조명 비교: 밝은 등 한 조건만 측정. 어두운 방(이전 기록의 15 fps 상태)에서 `-7`이 동작하는지 모름
- 수동 노출 복구: `--exposure -7` 종료 후 다시 열면 24 fps/gain 1 또는 30 fps/gain 192로 나타남. 밝기는 128~148로 원래 수준이나, 자동 노출이 완전히 복구됐는지는 조명을 바꿔 확인하지 못함. 자동 노출 상태도 24/30 fps 두 가지로 나타남 (`extra`, `auto`)
- 유령 점 잔존: repA 46%, exp6 14%, 자동 노출에서 잘못 잡힌 두 번째 손 추적이 유지되는 것으로 추정. 미확인, 미수정
- 양손 추적 뒤바뀜은 단위 테스트로만 확인

측정 도구는 scratchpad의 임시 스크립트이며 커밋하지 않았다. 녹화 프레임은 사용자 안내대로 작업 후 삭제.

### 사람 검증 (2026-11-06, 사용자)
`hand_sensor.py --exposure -7 --preview`, `CombatDev.unity`, `sensorMode: "external"`. 미리보기 끊김 감소, 빠른 흔들기로 실드 발동, 정지 시 미발동 모두 이상 없음. 테스트 후 `config.json` 원복, 센서 종료, 녹화 프레임 삭제 완료.

### 기획 세션 요청
`--exposure -7`을 계속 쓰려면 `config.json`에 `cameraExposure` 필드를 추가할지 결정 필요 (이 세션 범위 밖). 그 전까지는 `run_hand_sensor.bat --exposure -7`로 실행. `Tools/HandSensor`의 기본 동작은 그대로다.
