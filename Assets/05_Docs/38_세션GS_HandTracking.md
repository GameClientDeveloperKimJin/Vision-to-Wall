# 38. 세션 GS — Hand Tracking

- 담당자: **GS Hand Tracking**
- 브랜치: `feature/game-sensor-tuning`
- 담당: 빠르게 흔드는 손 인식 개선 (G3 사람 검증 중 사용자 보고)
- 수정 가능: `Tools/HandSensor/**`, 이 문서
- 선행 조건: G3 `main` 병합. 조사 중 사용자가 손을 흔들어야 하고 웹캠을 점유함

## 1. 문제

사용자 보고: "유저가 손을 빠르게 흔들었을 때 센서가 그 손을 제대로 인식을 못한다."

실드는 빠른 흔들기(`motion >= 0.8`)로 발동하므로, 이 문제는 게임 조작에 직접 영향을 줄 수 있다. 단, G3 사람 검증은 이 상태로 통과했다. **원인은 측정되지 않았다.**

## 2. 조사 순서

**원인을 측정한 뒤 고친다.** 추측으로 임계값부터 바꾸지 않는다.

1. 기준선 기록: `--preview` 상태로 약 20초씩, 손을 천천히 흔들 때와 빠르게 흔들 때의 `fps`, `hands`, `held`, `inferMs`
2. 조명 비교: 현재 조명과 밝은 조명에서 1을 반복. 카메라 fps 변화 기록
3. 측정 결과에 따라 시험

| 가설 | 근거 | 시험 |
|---|---|---|
| 모션 블러로 손을 놓침 | 어두우면 카메라가 약 15 fps, 노출이 길어짐 | 밝은 조명, 수동 노출 |
| 카메라 설정 미적용 | `open_camera`가 해상도만 설정, `cameraFps` 미사용. 이전에 MJPG/30fps 요청이 무시된 기록 있음 | FOURCC, fps, 노출 요청 후 실제 적용 값 확인 |
| 인식 신뢰도가 높음 | 현재 0.5 | 낮춘 값에서 놓침과 오검출 비교 |
| 놓친 동안 강도 감소 | 0.3초 hold 동안 위치 고정, `v` 감소 | hold 시간과 감소 곡선 비교 |

여러 조건을 한 번에 바꾸지 않는다. 시험마다 조건 하나만 바꾸고 수치를 기록한다.

## 3. 제약

- UDP 패킷 형식과 포트 변경 금지. Unity 코드 변경 금지
- 카메라 설정 추가가 필요하면 `config.json`의 기존 필드만 사용. 새 필드가 필요하면 기획 세션에 요청
- 오검출(손이 없는데 인식)이 늘어나는 변경은 수치와 함께 보고
- 하드웨어 한계로 판단되면 코드를 억지로 바꾸지 말고 "조명 조건"과 측정값을 결론으로 보고. 이것도 정상적인 결과임
