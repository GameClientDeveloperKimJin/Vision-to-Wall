### 세션 교대 절차
1. 작업 세션: 체크리스트 완료 → 자기 브랜치 커밋·push → 작업 로그 기록
2. 사용자: 같은 폴더(같은 Unity 에디터)에서 검증 항목 확인
3. 기획 세션: 자기 브랜치 → `main` 병합 + `AppBootstrap` 연결 → push
4. 다음 세션: `git checkout feature/<모듈> && git merge main` 후 착수 (앞 모듈 실제 코드 사용 가능)

## 3. 공통 규칙 (전 세션)

### 3.1 의존성
- 모듈 간 직접 참조 금지. Sensor / Network / Render / UI는 **Core만 참조**.
- 모듈 연결은 `App` 어셈블리(`AppBootstrap`)에서만 함. 담당: 기획 세션.
- Core 변경이 필요하면 코드를 직접 고치지 말고 기획 세션에 요청.

### 3.2 파일 소유권
- 자기 담당 폴더 밖 파일 수정 금지.
- **씬(`.unity`) 수정 금지** (기획 세션 전용). 각 모듈은 프리팹 또는 MonoBehaviour로 납품.
- 테스트용 씬이 필요하면 자기 폴더 안에 `Dev/` 하위로 생성 (예: `02_Scripts/Render/Dev/RenderDev.unity`). 통합 빌드에는 포함 안 됨.
- **공용 파일 커밋 금지** (기획 세션 전용). Unity가 자동으로 바꿔도 커밋 전에 되돌릴 것:
  - `ProjectSettings/**`, `Packages/manifest.json`, `Packages/packages-lock.json`
  - `Assets/Settings/**` (URP 에셋, `InputSystem_Actions`), `Assets/TextMesh Pro/**`, `Assets/01_Scenes/**`, `Assets/02_Scripts/Core/**`
  - 되돌리기: `git checkout -- ProjectSettings Packages Assets/Settings`
  - 패키지 추가, 렌더러 기능(Renderer Feature), Player Settings 변경이 필요하면 기획 세션에 요청 → `main`에 반영 후 각 세션이 `git merge main`
- **Build Settings에 Dev 씬 추가 금지.**
- TMP 기본 리소스는 `main`에 임포트되어 있음 (`Assets/TextMesh Pro/`). 다시 임포트하지 말 것.
- 커밋 전 확인: `git status`에 자기 담당 폴더 + 자기 문서 외 파일이 있으면 커밋하지 말 것.

### 3.2.1 Core 변경 반영 절차
1. 세션이 기획 세션에 변경 요청 → 2. 기획 세션이 `main`에 커밋·push + `01_Core_공통계약.md` 변경 이력 기록 → 3. 각 세션이 `git fetch && git merge origin/main`

### 3.3 코드 규칙
- 네임스페이스: `VisionToWall.<모듈>` (예: `VisionToWall.Sensor`)
- **Zero-GC**: `Update`, 수신 루프, 콜백 안에서 `new`, LINQ, 문자열 연결, 박싱, 람다 캡처 금지. 버퍼는 `Awake`/`Start`에서 미리 할당.
- 백그라운드 스레드에서 Unity API 호출 금지.
- 스레드/소켓은 `OnDisable` 또는 `OnDestroy`에서 반드시 정리 (에디터 Play 반복 시 포트 점유 방지).
- 매직 넘버 금지 → `AppConfig` 또는 `MotionProtocol` 상수 사용.

### 3.4 Git 규칙
- 각 세션은 자기 브랜치에서만 커밋 (작업 시작 전 `git branch --show-current` 확인).
- 커밋 메시지: `<type>(<module>): FR-xx 요약` (예: `feat(sensor): FR-03 frame diff detection`)
- 체크리스트 갱신은 **자기 문서만** (병합 충돌 방지). `00_개발_개요.md`는 기획 세션만 수정.
- `main` 병합은 기획 세션이 수행.
- 원격: `https://github.com/GameClientDeveloperKimJin/Vision-to-Wall` (private). 각 세션은 자기 브랜치만 `git push origin feature/<모듈>`. `main` push는 기획 세션만.

### 3.5 Unity MCP 사용 (전 세션)
- 패키지: `com.coplaydev.unity-mcp` v10 (MCP for Unity). 서버: `http://127.0.0.1:8080/mcp` — 프로젝트 루트 `.mcp.json`에 등록됨.
- 사용 전 Unity 에디터에서 `Window > MCP for Unity` 서버 실행 상태 확인. 세션 시작 후 `/mcp`로 `UnityMCP` 연결 확인.
- Unity 에디터는 `InteractiveGame` 하나만 사용. 브랜치를 바꾼 직후엔 반드시 `refresh_unity`로 리임포트·컴파일.
- 필수 루틴 (코드 수정 후 매번):
  1. `refresh_unity` (`compile: request`, `wait_for_ready: true`)
  2. `read_console` (error, warning) → 에러 0 확인
  3. 테스트 있으면 `run_tests` (EditMode) → `get_test_job`
- 씬/프리팹 조작(`manage_scene`, `manage_gameobject`, `manage_prefabs`)은 자기 `Dev/` 씬과 자기 프리팹에만.
- 성능 검증: `manage_profiler`로 GC Alloc 확인 가능.
- `execute_code`는 확인용 조회에만 사용. 에셋 변경은 전용 도구 사용.
