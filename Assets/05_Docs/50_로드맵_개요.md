순서 근거:
- R1은 이미 계산 중인 보스 각도만 쓰므로 가장 작고, 요구사항의 미충족 항목(디바이스 제어)을 바로 채운다.
- R2 → R3 → R4는 관절 스트림 하나를 공유한다. 스트림(R2)을 먼저 고정해야 R3, R4가 실제 관절로 시험할 수 있다. 미니 캐릭터(R3)는 관절을 그대로 보여주므로 스트림 품질을 먼저 확인하는 역할도 한다.
- R5는 외부 API 키와 전시장 네트워크 조건이 필요해서 마지막.

## 2. 사용자 결정 (2026-11-08)

| 항목 | 결정 |
|---|---|
| R1 시리얼 장비 | **시뮬레이션만**. 패킷 생성, 로그, 화면 속 가상 무빙라이트. 실제 COM 포트 송신 없음 (API 호환 수준 .NET Standard 2.1 유지) |
| R3 미니 캐릭터 모양 | **네온 관절 인형**. 관절은 빛나는 점, 뼈는 선 |
| 합성 영상 자동 검증 | R3에서는 하지 않음. **R4 직전 별도 세션(RT)**. 모델은 사용자가 Mixamo로 리깅한 `PlayerAvatar_Rig.fbx`, 동작은 코드 자세 (2026-11-08). R4의 VARCO 리깅도 불필요해짐. R3는 짧은 사람 검증 후 병합 |
| RT 판정 기준 | R3 미니 캐릭터는 **정면 2D 각도**로 판정 (2D로 그리므로). 3D 팔꿈치·무릎 실패는 R4 입력 품질 기록으로 유지 (`PoseClipDataTests.KnownFailure`). 기획 세션 결정, 2026-11-08 |
| 패링 규칙 | **팔 들기 실드 추가 (A안)**, 빠르게 흔들기 유지. 사용자 결정, 2026-11-08 |
| 아바타의 보스 가림 | 보스 눈 주변에 들어온 아바타 점만 흐리게 (크기·판정 유지). 사용자 결정, 2026-11-08 |
| R3 미니 캐릭터 표시 | **미디어 월에서만 표시**, 각성 때 사라지고 복귀 후 다시 표시. 전투 중 동작은 R4 아바타가 보여줌 |
| 전투 아바타 포즈 | **포함** (R4). 리깅된 모델이 필요하며 VARCO 비용은 사용자 승인 |

## 3. 세션 시작 절차와 공통 규칙

[30번 문서](30_게임_개요.md) 2절(시작 절차)과 3절(공통 규칙)을 그대로 따른다. 추가 규칙:

- 각 세션 착수 전에 기획 세션이 그 세션 문서의 "기획 세션 선행 작업"(Core 계약, config 필드)을 `main`에 넣는다. 세션은 `git merge main` 후 시작
- 새 config 필드는 기본값에서 기존 동작이 바뀌지 않아야 한다 (기능 꺼짐 또는 기존 값과 동일)
- 새 UDP 포트는 9002 하나만 사용 (R2, R3, R4 공유). 9000·9001 패킷 형식 변경 금지
- 외부 API 키, 계정 정보는 커밋 금지 (R5)
- VARCO 생성은 프롬프트와 예상 크레딧을 보여주고 사용자 승인 후 실행, 시험 1건 먼저 (R4)
