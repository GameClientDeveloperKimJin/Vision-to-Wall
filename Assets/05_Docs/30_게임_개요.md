## 2. 세션 시작 절차

1. **앞 세션 병합 확인**: `git log main --oneline -5`와 4절 현황표로 앞 세션이 병합됐는지 확인. 안 됐으면 시작하지 말 것
2. 세션을 `D:/UnityProject/3D/InteractiveGame`에서 열고 `/rename <세션 이름>`
3. Unity 에디터 실행, MCP 서버 시작 후 `/mcp`로 `UnityMCP` 확인
4. 첫 지시: **"`30_게임_개요.md`, `31_게임_공통계약.md`, 내 세션 문서를 읽고 체크리스트대로 진행해."**
5. 브랜치 전환: `git checkout feature/game-<이름> && git merge main`

MCP 도구가 안 붙으면 `http://127.0.0.1:8080/mcp`를 HTTP로 직접 호출해도 된다.

## 3. 공통 규칙

`00_개발_개요.md` 3절 규칙을 그대로 따른다. MVP에서 실제로 문제가 됐던 항목은 다음과 같다.

### 파일 소유권
- 자기 세션 문서의 "수정 가능" 경로만 수정. 나머지는 기획 세션에 요청
- `Assets/01_Scenes/**`, `App/AppBootstrap.cs`, `Core/**`, `ProjectSettings/**`, `Packages/**`, `Assets/Settings/**`, `Assets/06_Font/**`는 기획 세션 전용
- 커밋 전 `git status` 확인. `git add -A` 금지, 경로를 지정해서 stage

### 커밋하면 안 되는 변경
- `Assets/06_Font/**`: Play하면 글리프가 추가되어 항상 수정됨 → `git checkout -- Assets/06_Font`
- `Assets/01_Scenes/Main.unity`: 씬을 열 때 `EngineerPanel`의 레이아웃 값(0)과 TMP 해시가 오버라이드로 기록될 수 있음. 세션 작업 원인이 아니며 `git checkout -- Assets/01_Scenes/Main.unity`로 되돌림
- `Assets/StreamingAssets/config.json`: 테스트로 바꾼 값(`sensorMode`, F1 슬라이더 저장값)은 끝나면 되돌릴 것

### 테스트
- Play 테스트는 **Unity 창이 포커스된 상태**에서만 유효. 비포커스면 프레임이 멈춰 패킷 pool drop이 생김
- 웹캠은 한 프로그램만 열 수 있음. `hand_sensor.py` 실행 중에는 `sensorMode: "external"` 필수
- Play 중 MCP `execute_code` 호출은 메인 스레드를 잠깐 멈춰 패킷 pool drop을 만듦. Drop 수치는 조회를 멈춘 구간으로 판단
- 한 포트에 송신자 둘이면 seq 충돌로 drop 발생 (Unity 센서 + `fake_sender.py` 동시 사용 금지)
- 테스트 씬은 자기 폴더 `Dev/`에 생성. Build Settings 추가 금지

### 코드와 UI
- 프레임 루프·콜백 Zero-GC. 상태 전환 시점의 1회성 할당만 허용
- 입력은 Input System 전용 (`UnityEngine.Input` 금지)
- 타이머는 `Time.unscaledTime` (결과 연출에서 슬로우 모션을 쓰므로 판정이 영향받으면 안 됨)
- `Time.unscaledDeltaTime`을 누적할 때는 `GamePhaseMachine.MaxFrameDeltaSec`(0.1초)로 제한. Play 진입 프레임에 3.8초가 측정된 적 있음
- 모든 TMP 텍스트는 `Assets/06_Font/GmarketSansTTFMedium SDF.asset`. `…` 글리프가 없으므로 Ellipsis 금지
- 빌더로 프리팹을 재생성하면 씬의 컴포넌트 참조가 끊길 수 있음 → 인계 사항에 적을 것
- 한글이 들어간 파일 수정은 Edit/Write 도구 사용 (셸 heredoc으로 쓰면 깨진 사례 있음)

### 완료와 교대
1. 구현·자동 검증 체크리스트 완료 후 자기 브랜치 커밋·push
2. 사용자에게 **열 씬 → 할 동작 → 기대 결과** 3줄로 사람 검증 요청 (세션당 최대 3개)
3. 통과하면 기획 세션에 병합 요청: 커밋, 검증 수치, 통합 인계 사항
4. 기획 세션이 범위 확인 → `main` 병합 → `AppBootstrap`/`Main.unity` 연결 → 다음 세션 착수 가능 표시

## 5. 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 몸 위치 입력 | MediaPipe Pose를 손 센서 프로세스에 추가, **UDP 9001 별도 스트림** | 회피(G-FR-06)에 몸 위치가 필요. 웹캠을 한 프로세스가 공유하고, 패킷 형식과 9000 스트림은 그대로 유지 |
| 몸 스트림이 없을 때 | 모션 포인트 무게중심으로 대체 | `sensorMode`를 아직 정하지 않았으므로 두 모드 모두 플레이 가능해야 함 |
| 기존 상태 머신 | `ExhibitionStateMachine` 유지, `GamePhase`를 별도로 둠 | 대기/체험은 미디어 월 단계 안에서만 의미 있음. 전투 중 안내 문구는 게이트로 차단 |
| 공격 방식 | 조준선 → 탄막 1종 | 패링이 보스 HP를 깎는 유일한 수단. 레이저 빔은 조준선 연출로 표현 |
| 회피 판정 시점 | 조준 위치를 발사 직전 고정, **탄막 도착 시 판정** | 발사 순간까지 플레이어를 따라가며 즉시 판정하면 회피가 불가능함 |
| 3D 카메라 | 기존 직교 카메라 위에 URP Overlay 원근 카메라 | 월 쉐이더를 건드리지 않고 보스에 원근감 부여 |
| 아트 컨셉 | 사용자 레퍼런스 `Assets/04_Docs/eye_of_the_future_art_reference.png` | 사용자 전달 (2026-11-06). 전투 화면의 기준 이미지 |
| 보스 모델 | VARCO는 금속 링 외피, 홍채는 쉐이더 | 베이크된 텍스처로는 HDR 발광과 눈 감김, 각성 전환을 표현할 수 없음 |
| 탄막 표현 | 파편 모델 없이 빛 탄과 트레일 (G5) | 레퍼런스에 파편이 없음. 판정은 G3 그대로 (`projectileFlightSec`) |
| 미디어 월의 보스 | 숨김. 게이지 0.25부터 파티클이 모이는 자리에서 자라남 | 사용자 결정 (G5 사람 검증, 2026-11-07). 요구사항 Phase 1의 "불 꺼진 조형물"을 대체 |
| 플레이어 표현 | 뒷모습 인간형 모델을 점으로 렌더링, 몸 위치로 이동 | 몸 스트림은 중심 좌표 1개뿐이라 **팔다리는 실제 동작을 따라가지 않음**. 실제 포즈 반영은 미니 캐릭터와 같은 랜드마크 스트림이 필요하므로 로드맵으로 둠 |

### 보류 중 (사용자 결정)
- 기본 `sensorMode` (`webcam` / `external`)
- 카메라 노출 기본값: `config.json`에 `cameraExposure` 추가 여부. 결정 전까지 `run_hand_sensor.bat --exposure -7`로 실행
- 대기 안내 문구 ("손을 흔들어 보세요" 유지 중)
- 실제 Windows 빌드, v2.1(시리얼), v2.2(날씨 API)는 게임 완성 후
- 아트 컨셉 (사용자가 추후 전달)

게임 요구사항에 없는 수치(HP, 실드 시간 등)는 [31번 문서](31_게임_공통계약.md)에 기본값으로 정했고 config에서 조정한다.
