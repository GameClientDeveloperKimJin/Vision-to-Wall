### 4. 체험 시나리오
- 메시지: 설명 없이 손짓만으로 시작해서 끝나고, 다음 사람을 위해 스스로 돌아온다 (설계 의도: "간단하게 손을 흔들다가 자연스럽게 보스전으로")
- 초안 (4단계 흐름도): 대기(미디어 월) → 각성(7초 흔들기, 2초 연출) → 전투(60초, 회피·실드·패링) → 결과(5초) → 대기 복귀. 사람이 떠나면 10초 뒤 자동 종료
- 설계 포인트: ① 미디어 월에서 쓰던 "내 손의 파티클"이 그대로 보스로 빨려 들어가 각성의 이유가 됨 ② 각성 요구 시간 7초 = 지나가는 손짓으로는 시작되지 않고, 의도한 사람만 시작 ③ 미니 캐릭터는 대기 중에만(인식 피드백), 전투 중에는 아바타가 같은 역할 (정보 중복 제거)

### 8. 문제 해결 (기존 포트폴리오의 4칸 형식, 3~4건)
| 건 | 증상 | 원인 | 해결 | 결과 |
|---|---|---|---|---|
| ① 빠른 손을 놓침 | 빠르게 흔들면 손 인식이 끊겨 실드가 안 켜짐 | 측정: 같은 속도에서 자동 노출 36.1% 놓침 vs 노출 -7 0.0% → 모션 블러 | 수동 노출 옵션 + 다시 잡은 손을 같은 손으로 이어 붙이는 매칭 수정 | 놓침 36.1% → 0%, 유령 점 25.9% → 1.7% (38번 문서) |
| ② 아바타가 의도대로 안 움직임 | 팔을 들면 엉뚱한 방향 | 대조 녹화 도구로 2205프레임 분석: 근접 구도로 팔이 화면 밖(63%), MediaPipe 깊이 편향 15~22 cm | 화면 방향은 2D 관절에서, 다시 보인 팔 0.1초 복귀, 설치 요건 도출 | 어긋남 중앙값 10.6° → 1.5°, 어긋난 구간 8 → 0 (57번) |
| ③ 팔을 들었는데 패링이 안 됨 | 레이저 타이밍에 팔을 들어도 실패 | 규칙은 "빠르게 흔들기"인데 아바타가 팔을 따라 하면서 화면이 "팔 들기"를 유도 | 팔 들기 시작 순간 실드 추가, 쿨다운 중 든 팔은 기억했다 발동 | 사용자 검증 통과, 흔들기 실드도 유지 (58번) |
| ④ 웹캠 해상도 성능 | 1280×720에서 8 fps | USB2 무압축 대역폭 | 640×480 | 8 → 25 fps (MVP) |
- 넣을 화면: ①은 미리보기 프레임 놓침 그래프, ②는 사람·아바타 나란히 비교 이미지(얼굴 가림), ③은 실드 장면
- 추가 후보: 아바타가 화면을 보는 듯한 문제(뒷면 점이 비침 → 척추·견갑골 셰이더), 보스 가림(보스 근처 점 흐리게), 프레임 할당 0 유지

### 9. 회고 / 확장 계획
- 회고: 게임 개발 경험(전투 판정, 연출, 최적화)을 전시 체험에 그대로 옮김 / AI 세션을 순차로 나눠 기획·계약·검증·병합을 직접 지휘 (세션 20여 개, 문서 29개, 테스트 470개)
